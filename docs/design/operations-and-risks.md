# 操作とリスク

IdP を通じてできる行為を主体ごとに洗い出し、目的、悪用や誤りのときに誰が影響を受けるか、今の対策を並べる。誰に何を任せるか（AI を含む）は、職種ではなくこの一覧の影響の広さで決める（[認可](authorization.md)、[管理 CLI と管理用の Worker](idpctl.md)参照）。管理の行為は、`idpctl` から管理用の Worker の管理 API を通じて行い、どれも mTLS と許可リストで確定した管理者だけができ、監査ログに管理者の名前が残る。

**利用者（ブラウザ）**

| 行為 | 目的 | 悪用・誤りの影響 | 今の対策 |
| --- | --- | --- | --- |
| パスキーの登録 | 本人と端末を結び付ける | 登録リンクを他人が使うと、その人として全 RP に入れる | 10 分、1 回だけ、対面で渡す |
| パスキーの追加 | 本人が端末を増やす | 本人の認証器と UV を押さえた攻撃者が、パスキーを足して居座る | 直前の再認証、[パスキーの上限](cross-language-contract.md)、監査ログ（本人への通知はない） |
| パスキーの失効 | 失くした端末のパスキーを止める | 本人の認証器と UV を押さえた攻撃者が、本人の他のパスキーを消して締め出す | 直前の再認証、最後の 1 本は失効できない、監査ログ、管理者による復旧 |
| サインイン | 本人を確認してセッションを作る | セッションを盗まれると、1 時間その人として許可済みの RP に入られる | `__Host-` Cookie、SameSite=Lax、1 時間の絶対期限 |
| サインアウト | 共用の端末で次の人に使わせない | 強制的にサインアウトさせられる（軽微） | 同一オリジンの確認 |

**RP（OIDC）**

| 行為 | 目的 | 悪用・誤りの影響 | 今の対策 |
| --- | --- | --- | --- |
| 認可の要求 | ユーザーにサインインしてもらう | redirect 先を乗っ取られると、認可コードを盗まれる | redirect URI の完全一致、PKCE |
| トークンの交換 | 本人の情報を受け取る | シークレットが漏れると、その RP を名乗られる | クライアント認証、PKCE、60 秒のコード |
| `/userinfo` | 最新の属性を取る | アクセストークンが漏れると、5 分間読まれる | 毎回アクセス可否を確認し直す |

**ユーザーの管理（idpctl）**

| 行為 | 目的 | 悪用・誤りの影響 | 今の対策 |
| --- | --- | --- | --- |
| ユーザーの作成 | 人を迎える | grant がなければ実害はない | 監査ログ |
| 登録リンクの発行 | 初回の登録、パスキー紛失からの復旧 | 任意のユーザーとして、その人の全 RP に入れる | 10 分、対面、平文はファイルだけ、本人性を確定させる操作として分類する、[パスキーの上限](cross-language-contract.md)に達したユーザーには発行しない |
| パスキーの失効、無効化、セッションの失効 | 事故対応、退去 | 正当な人を締め出す（可用性） | 再登録か `user_enable` で復旧できる。パスキーの失効は最後の 1 本を残す（完全に止めるのは無効化）。ユーザーは削除しない |
| ユーザーの有効化（`user_enable`） | 誤った無効化を戻す、戻ってきた人を迎える | 締め出したはずの人（や、その人のパスキーを持つ攻撃者）を戻す | 監査ログ、今と同じ状態への変更は拒否する |
| 表示名とグループ名の変更 | 事実を正しく保つ | 別人やほかのグループと取り違えさせる | ID は変わらない、変更前後の名前を監査ログに残す |
| グループのメンバーの変更 | 人についての事実を保つ | そのグループに付いた全 RP へのアクセスを間接的に与える | 権限が広がる範囲を表示し、監査ログに残す |
| グループの無効化と有効化（`group_disable`、`group_enable`） | グループ経由のアクセスをまとめて止める、戻す | 無効化はメンバー全員を締め出し、有効化はメンバー全員にグループの grant をまとめて戻す | 監査ログ、所属と grant は残るので戻せる、グループは削除しない |

**RP とアクセスの管理（idpctl）**

| 行為 | 目的 | 悪用・誤りの影響 | 今の対策 |
| --- | --- | --- | --- |
| RP の登録 | 新しいアプリをつなぐ | grant がなければほぼない（パスキーは IdP の origin に縛られる） | 監査ログ |
| redirect URI の変更 | 移転、環境の追加 | その RP の利用者全員の認可コードを盗める | 監査ログ |
| シークレットの更新 | 漏洩への対応 | 新しいシークレットで、その RP を名乗れる | 平文はファイルだけ |
| ID トークンの署名アルゴリズムの変更（`client_set_id_token_alg`） | Ed25519 を検証できない RP に RS256 を使わせる、戻す | その RP が ID トークンを検証できなくなり、サインインできなくなる | 監査ログ、RS256 が無効な間は `RS256` の登録を拒否する |
| RP の無効化と有効化（`client_disable`、`client_enable`） | 使わなくなったアプリを止める、戻す | 無効化はその RP の利用者全員を締め出し、有効化は残っている grant と redirect URI をそのまま戻す | 監査ログ、client は削除しないので ID が再利用されない、無効な client の `/authorize` はリダイレクトしない |
| grant | RP を使える人を決める | 主体（グループなら全メンバー）に、その RP を過剰に使わせる | 権限が広がる範囲を表示し、監査ログに残す |

**基盤（運用者）**

| 行為 | 目的 | 悪用・誤りの影響 | 今の対策 |
| --- | --- | --- | --- |
| 署名鍵の生成と登録 | トークンに署名する | 全ユーザーの全 RP 向けトークンを偽造できる | レビュー済みの生成スクリプトだけで生成する、平文をディスクにも AI のコンテキストにも出さない、1Password |
| D1 の API トークン | break-glass（管理用の Worker が使えないとき） | 上の管理の区分をすべて迂回でき、共有コアの規則も監査ログも通らない。トリガーを外せば行も消せる | 日常は使わない、前もって作らず、必要なときだけ短い有効期限で作って終わったら失効させる、IdP 専用アカウント |
| クライアント証明書の発行と失効 | 管理者に mTLS の証明書を渡す、止める | アカウントの managed CA で検証を通る証明書を、任意の主体名で作れる。失効させれば管理者を止められる | 「SSL and Certificates Write」を基盤の権限として扱う、証明書だけでは管理 API に入れない（許可リストが要る） |
| 許可リストの変更 | 管理者を足す、外す、証明書を更新する | 任意の証明書を管理者にできる | 管理用の Worker の設定としてリポジトリに置き、CI のデプロイでだけ変える。D1 にも管理 API にも置かない |
| Worker のデプロイと Terraform の apply | コード、設定（許可リストを含む）、基盤（DNS、WAF、mTLS）を更新する | コードや WAF のルールの差し替えで何でもできる | CI（GitHub OIDC、1Password Environments）。main へのマージで手動の承認なしに走るので、main のブランチのルールセット（PR のレビューとマージの権限）が唯一の関門になる |

**影響の広さ**

- 全ユーザー × 全 RP：署名鍵、D1 の API トークン、デプロイと Terraform の apply（許可リストの変更を含む）、main へのマージの権限。管理者になるには、証明書の発行と許可リストの変更の両方が要る。
- 1 人のユーザー × その人の全 RP：登録リンク。ユーザー 1 人分とはいえ、基盤に近い強さを持つ。メールアドレスを持たない（[トークン設計](tokens.md)参照）ので、`email_verified` による同じ段階の経路はない。
- 1 つの RP × その全利用者：redirect URI、シークレット、RP の無効化と有効化。
- 主体 × RP：グループのメンバーの変更、グループの無効化と有効化、grant。グループのメンバーの変更は、グループに付いた grant を通じて効く間接的な付与になる。
