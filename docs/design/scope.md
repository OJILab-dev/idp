# スコープ

最初に作るのは OIDC の認可コードフロー、パスキー、アプリ単位のアクセス制御、管理 CLI の 4 つだけ。それ以外は作らないか、必要になってから足す。

| 機能 | 判断 | 理由・備考 |
| --- | --- | --- |
| OIDC（discovery / JWKS / authorize / token / userinfo） | 作る | 認可コード + PKCE S256 のみ |
| パスキーの登録・サインイン | 作る | 唯一の認証手段 |
| IdP からのサインアウト（POST /logout）とセッション失効 | 作る | 共用の端末で使ったあと、次の人が確認なしでサインインできてしまうのを防ぐ |
| アプリ単位のアクセス可否（認可レベル 1） | 作る | `client_access` テーブルで管理 |
| 管理 CLI（`idpctl`） | 作る | Go 製。後から MCP でも操作可能にする |
| ネイティブアプリ・CLI（public client） | 作る | RFC 8252 に沿い、PKCE とループバックなどの redirect で守る。サインインは毎回パスキー（[クライアントの種類](clients.md)参照） |
| 管理 Web UI | 作らない | CLI で代替し、管理面をインターネットに出さない |
| 同意画面 | 作らない | クライアントはすべて管理者が登録する。public client には、同意画面の代わりに毎回パスキーを求める |
| DCR / CIMD / リモート MCP | 作らない | 必要になったら再検討 |
| メール送信・パスキー紛失時のセルフ復旧 | 作らない | 復旧は管理者が登録リンクを再発行する |
| OIDC のログアウト仕様（RP-Initiated Logout など） | 作らない | v1 では不要。IdP 側のサインアウトだけを用意する |
| ブラウザだけで動く SPA（public client）と client\_secret\_post | 作らない | SPA は BFF を置いて Web アプリとして登録する（RFC 10017）。confidential client の認証は client\_secret\_basic だけにする |
| リフレッシュトークン | 作らない | Secure by Default の方針。必要が生じたら、ローテーションと再利用検知を前提に再検討する |
| アプリ内ロール・API スコープ（認可レベル 2・3） | 後回し | 必要になったらマイグレーションでテーブルを足す |
| 課金・権利（entitlements） | IdP に入れない | 別サービス（ledger）で管理する |
| パスワード / TOTP / SAML / LDAP / ソーシャルログイン | 作らない | 思想の外 |
